The expr language has no error handling: runtime errors cause unrecoverable panics.

Add structured error handling built on first-class error values:

- `try(expression, fallback)` - returns the expression result on success or the lazily-evaluated fallback on error; requires exactly two arguments.
- `try { expr } catch { handler }` - block form with ordered catch arms. A block may carry several catch arms; arms are tried in order and the first matching arm runs. `catch <name> { ... }` binds the error and matches anything. `catch <name> is "substring" { ... }` matches only errors whose message contains the substring. `catch <name> is #tag { ... }` matches only errors whose tag equals `tag`. If no arm matches, the error propagates.
- `finally { cleanup }` - optional clause that always executes after try/catch; if the finally body throws, that error propagates and overrides any prior result.
- `throw(value)` - throws from any value; requires exactly one argument. Throwing an error value throws it as-is, preserving message, tag, metadata, and causes; any other value becomes an error whose message is its string conversion.
- `retry` - usable inside catch blocks, re-executes the try body; automatic limit of three retries before raising a distinct exhaustion error. Using retry outside a catch block raises a runtime error.
- `error(message)`, `error(message, tag)`, `error(message, tag, metadata)` - construct an error value without throwing it; message and tag are strings, metadata is a map. `errmsg(err)`, `errtag(err)`, `errmeta(err)` - accessors requiring an error value input (runtime error otherwise); a missing tag reads as `""` and missing metadata as `{}`.
- `errtype(err)` - classifies an error; requires exactly one argument. Returns `"index"` for out-of-range/bounds errors, `"conversion"` for type-conversion failures, `"type"` for type-mismatch/assertion errors, `"nil"` for nil-pointer/reference errors, `"retry"` for retry-exhaustion errors, `"tagged"` for errors carrying a non-empty tag, `"custom"` for all other errors including untagged `throw`/`error` values, `"none"` when the input is nil.
- `rethrow(err, context)` - throws a new error whose message is `context`, whose tag and metadata are empty, and whose cause is `err`; requires exactly two arguments and an error value first argument. `causes(err)` returns the array of error values from `err` outward through each cause to the root; `rootcause(err)` returns the innermost error. For an error with no cause, `causes` returns a one-element array and `rootcause` returns the error itself.
- `scoped { body }` with `defer(fn)` - `defer` registers a zero-argument callable in the nearest enclosing `scoped` block and errors at runtime outside one. On scope exit the deferred callables always run, last-registered first, whether the body succeeded or threw. If cleanup callables throw, their messages aggregate in execution order into one error with message `"cleanup failed"`, tag `"cleanup"`, and metadata `{"errors": [...]}`. A successful body followed by failing cleanup throws the aggregate; a failing body propagates the body error with the aggregate appended to its cause chain.
- Compilation must not defeat error handling: inside try constructs, expressions that fold to constant errors (for example a literal modulo by zero or a constant out-of-range index) still compile, and their errors remain catchable at runtime with correct classification. Outside try constructs, existing compile-time behavior is unchanged.
